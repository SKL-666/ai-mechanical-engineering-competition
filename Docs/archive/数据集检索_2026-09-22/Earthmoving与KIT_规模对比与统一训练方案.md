## 2. 数据集规模：已验证事实

### 2.1 体积口径

下表GB按10^9字节、MB按10^6字节换算。Earthmoving解压量按本地`Data/`所有文件逻辑大小求和，含少量元数据；KIT解压量由ZIP中央目录中的原始文件大小求和。**这不是文件系统实际占用块数，也不代表KIT已完整解压到本地。**

| 项目 | Earthmoving | KIT |
|---|---:|---:|
| 压缩包字节数 | 2,008,325,653 | 5,815,544,519 |
| 压缩包约值 | **2.01 GB** | **5.82 GB（5.42 GiB）** |
| 解压文件逻辑大小 | 2,047,412,013字节 | 5,821,357,745字节 |
| 解压文件约值 | **2.05 GB** | **5.82 GB** |
| 整包JPG | 89,066张连续帧 | 3,000张稀疏关键帧 |
| 整包MP4 | 本地以JPG帧提供 | 2,304个文件，含其他机械、测试素材和结果演示 |
| 挖掘机动作标注规模 | **479条动作区间，来自10段原视频** | **304段按动作目录组织的视频** |
| 挖掘机类别数 | 5 | 4 |
| 连续动作区间真值 | 已有，索引约定仍需核对 | 本轮未发现 |

KIT整包压缩体积约为Earthmoving的2.90倍。这个倍数不能解释为有效训练数据、独立场景或训练耗时也增加2.90倍。

### 2.2 对本任务有直接价值的KIT子集

| 子集 | 文件数量 | 未压缩逻辑大小 |
|---|---:|---:|
| 挖掘机4个动作目录中的MP4 | 304 | **818,324,161字节，约818 MB / 0.82 GB** |
| 挖掘机4类对应前缀的关键帧JPG | 1,500 | **535,776,087字节，约536 MB** |
| 整包所有机械关键帧JPG | 3,000 | 851,060,259字节 |
| 整包所有机械TXT标签 | 3,000 | 116,625字节 |

仅做挖掘机视频分类时，优先提取304段视频。训练不需要把全部其他机械和演示素材纳入。0.82 GB是所需视频条目的未压缩大小，不是已经存在的独立子集下载包大小；选择性获取仍需下载整包后提取，或使用支持ZIP分段读取的工具。

关键帧与视频有素材关联，不能把1,500张图当作额外1,500个独立视频样本。Earthmoving的479条区间与KIT的304个片段也不是严格等价的计量单位。后续子集下载后，已从MP4元数据统计KIT视频轨道总时长900.633秒（约15.01分钟）、单段0.567–5秒；291段平均30 FPS、13段25 FPS。没有完整解码；这些统计不能由论文固定片长推算，Earthmoving时间轴仍待核实。

## 3. 建议的统一训练架构

```text
Earthmoving：JPG帧目录 + 原动作区间
                ↓ Earthmoving适配器
              统一样本索引
                ↑ KIT适配器
KIT：按动作目录组织的MP4
                ↓
       统一采样、空间处理和归一化
                ↓
   视频张量 [C, T, H, W] + 标签 + 来源
                ↓
      同一个模型、训练循环和评价出口
```

原始数据保持各自格式。Earthmoving无需重编码为MP4，KIT也无需全部预先解码成JPG。分别使用帧目录读取器和视频读取器，在模型输入处统一；整个batch通常为`[B, C, T, H, W]`，最终维度排列依所选框架约定。

### 3.1 候选标签映射：必须核实后才启用

保留Earthmoving原始编号作为统一模型输出，**严禁直接拼接两套数据的原始class_id**。

| 统一ID | 统一类别 | Earthmoving原ID/类别 | KIT原ID/类别：候选映射 |
|---:|---|---|---|
| 0 | Idle | 0 / Idle | 无 |
| 1 | Swing Bucket | 1 / Swing Bucket | 2 / Hauling、3 / Swinging |
| 2 | Load Bucket | 2 / Load Bucket | 0 / Digging |
| 3 | Dump | 3 / Dump | 1 / Dumping |
| 4 | Move | 4 / Move | 无 |

KIT原ID来自8类标签文件的抽样读取，不是对全部标注一致性的证明。需要将标签文件、目录类别、视频样例和论文定义对应起来，尤其确认Hauling是否是载料回转而非整机移动。核对现有标签语义不等于新增人工补标。

映射成立后，KIT缺少Idle/Move不妨碍参与5类分类训练，但不能把KIT缺失标签当作背景类，或宣称补足了这两类数据。原始标签必须保留，以便追溯合并关系。

若映射不能确认，备选为**共享特征骨干、Earthmoving 5类头与KIT 4类头分开**，按来源计算相应损失。该方案可共用训练入口，但增加实现与实验复杂度，未确定采用。

### 3.2 统一样本索引的最低字段

可用JSONL保存，每条记录表示一个拟训练片段：

| 字段 | 用途 |
|---|---|
| `sample_id` | 含来源前缀的唯一样本ID，避免跨集重名 |
| `dataset` | `earthmoving`或`kit` |
| `source_group` | 原始拍摄视频/同源素材组，负责划分隔离；不能简单等于切片文件名 |
| `media_type` | `frame_dir`或`video` |
| `media_path` | 原始媒体路径；若相对数据根目录，配置中明确该根目录 |
| `start_frame` / `end_frame` | 适配后0起始、左闭右开区间；保留原始索引映射依据 |
| `fps` | 经来源或实际媒体核实的帧率，不能从JPG推定 |
| `raw_label` | 发布者原编号与名称 |
| `label` | 经审核映射后的统一编号 |
| `split` | `train` / `val` / `test` |

有设备框或多设备时补充`equipment_id`、框来源/路径和裁剪策略。索引元数据还应记录标签映射版本、采样参数、源文件清单哈希和忽略规则。

- Earthmoving适配器：读取原动作区间，完成编号对齐后构建分类片段；未标注、重叠冲突等范围按明确规则忽略，不能自动填成Idle。
- KIT适配器：首版仅纳入已确认动作目录下的挖掘机MP4；逐个检查可解码性、帧数、FPS和目录标签。其他机械、仅有Test Video名称的素材和预测演示默认不纳入监督训练。

### 3.3 输入和裁剪保持一致

例如可配置每片段16帧、统一输入尺寸和归一化；16只是示例，不是最终选定参数。配置同时明确采样时间跨度，利用实际FPS换算，避免两套数据相同帧数却对应不同时间长度。短片段的补齐/忽略规则需显式记录。

随机裁剪、翻转等空间增强在同一片段各帧使用一致参数，避免制造虚假运动。

Earthmoving有逐帧设备框；KIT主要是稀疏关键帧框，尚未完成关键帧到MP4的时间对应。可先用整帧片段跑通统一分类基线，作为有场景背景影响的基线报告。改用目标裁剪时，统一框来源、框与帧对齐及裁剪规则，不默认给KIT每帧已有真值框。

模型与框架尚未冻结；MMAction2/TSM仍只是既有候选，统一索引与读取器设计不绑定某个具体网络。

## 4. 统一入口与公平对照

以下是**拟建接口示例，不是当前可执行命令**；模块和配置文件尚不存在：

```bash
python -m action_recognition.train --config configs/earthmoving_only.yaml
python -m action_recognition.train --config configs/earthmoving_kit.yaml
```

| 实验配置 | 训练来源 | 评价要求 |
|---|---|---|
| Earthmoving基线 | Earthmoving训练部分 | 固定的Earthmoving验证/测试划分 |
| 联合训练 | Earthmoving训练部分 + KIT训练部分 | 使用同一个Earthmoving测试集；另报KIT留出集上有支持类别的结果 |

统一模型、预训练初始化、输入处理、优化器、评价单位与输出目录。训练预算也要可比较，记录优化更新步数和样本曝光量；不能在加入KIT后仅保持epoch数相同就称预算相同。

每条预测保留数据集来源。分别报告Earthmoving与KIT指标，不能只报混合总体Accuracy掩盖某一来源下降。KIT没有Idle/Move，其4个原始类别若按候选映射合并，实际只覆盖统一标签中的3类；报告清楚类别集合与support，不把缺失类别的F1解释为已测能力。详细输出继续遵循[3号任务说明](../../3号同学_动作识别任务说明.md)。

## 5. 防止数据泄漏与来源失衡

1. **先分组划分，再切片或滑窗。**同一原始视频、连续拍摄源、相邻片段及其图像/增强派生必须处于同一划分。
2. 检查Earthmoving与KIT是否复用了同一网络视频；跨数据集去重，同源素材不可分别落入训练和测试。只有文件CRC不同不能证明场景独立。
3. KIT关键帧与MP4的发布划分不同，不将两条数据管线按各自train/val直接拼接。先建立媒体对应和统一来源组；无法恢复独立来源时记录限制。
4. KIT实测数量与论文表格有差异，以清单为准。不能将论文600段或2,680/320关键帧划分当成已下载包事实。
5. 可以把每批Earthmoving/KIT约1:1作为来源采样起点，**比例是待验证超参数**，由验证集选择。按窗口总量直接采样容易被切片更密的一方主导。
6. 类别权重只根据训练集统计，注明按区间还是训练窗口统计；测试标签不得用于调权重、阈值或映射。
7. Earthmoving的Move只有4条原始区间。过采样会重复已有信息，不能增加独立场景或替代缺失的测试支持。

## 6. 片段监督与连续序列评价分开

- 联合训练入口用于片段分类，既可读取Earthmoving区间内片段，也可读取KIT预切视频。
- 连续推理使用固定滑动窗口和真实设备轨迹，不使用测试真值动作边界触发切片或平滑。
- 片段分类指标不等同于连续动作分段指标。KIT没有已核实的长视频区间真值，因此连续动作边界和序列评价主要依靠Earthmoving。
- Earthmoving原有Swing Bucket未区分满斗回转与空斗返回；即使加入KIT，也不能在保留5类输出的同时声称模型独立输出了这两种动作。
- 正常动作标注仍不能直接推出漏步骤、错序等工序异常真值，异常判断与评价按既定分工交由4/6号落实。
