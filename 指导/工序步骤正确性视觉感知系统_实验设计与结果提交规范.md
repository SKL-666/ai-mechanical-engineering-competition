# 工序步骤正确性视觉感知系统
## 实验设计与结果提交规范 V1.0

## 一、实验目标

本项目实验主要回答以下 5 个研究问题：

| 编号 | 研究问题 |
|---|---|
| RQ1 | 系统能否准确识别施工场景中的设备、目标及动作？ |
| RQ2 | 引入动作时序信息后，是否能提高工序识别与判断能力？ |
| RQ3 | 系统能否准确检测漏工序、错序、重复步骤等异常？ |
| RQ4 | 在扬尘、暗光、逆光、遮挡等复杂环境下，系统是否仍具有较好的鲁棒性？ |
| RQ5 | 系统整体推理速度和资源占用能否满足实时部署要求？ |

最终论文、答辩和技术报告均围绕以上五个问题展开。

## 六、工序正确性判断实验

对应 **4号负责人**，也是本项目的核心实验。

假设标准工序为：

```text
挖掘 → 提升 → 回转 → 卸料 → 返回
```

需要覆盖以下类型：

### 1. 正常工序

```text
挖掘 → 提升 → 回转 → 卸料 → 返回
```

### 2. 漏步骤

```text
挖掘 → 提升 → 卸料 → 返回
```

例如漏掉“回转”。

### 3. 顺序错误

```text
挖掘 → 回转 → 提升 → 卸料 → 返回
```

### 4. 重复步骤

```text
挖掘 → 提升 → 提升 → 回转 → 卸料
```

### 5. 非法动作

```text
挖掘 → 提升 → 未定义动作 → 卸料
```

需要统计：

| 异常类型 | Precision | Recall | F1 | 检测数量 |
|---|---:|---:|---:|---:|
| 漏步骤 | | | | |
| 顺序错误 | | | | |
| 重复步骤 | | | | |
| 非法动作 | | | | |
| 综合 | | | | |

本项目建议重点关注：

- Recall
- F1

因为工序监管场景中，异常是否能够被及时发现比单纯 Accuracy 更重要。

## 七、最重要的对比实验：是否需要时序判断

比较三种方案：

| 方法 | 单帧识别 | 动作序列 | 工序规则 | 工序判断 F1 |
|---|---|---|---|---:|
| 方法1 | ✓ | × | × | |
| 方法2 | ✓ | ✓ | × | |
| 完整系统 | ✓ | ✓ | ✓ | |

该实验回答：

> 为什么不能只使用普通目标检测或单帧动作识别，而需要额外加入时序与工序逻辑？

如果完整系统明显优于前两种方法，即可证明时序工序校验模块的实际价值。

# 十二、所有成员统一实验规则

## 1. 所有结果禁止只发截图

必须同时提交：

```text
原始 CSV
+
实验图片
+
README
```

否则无法统一生成论文表格和统计结果。

---

## 2. 所有实验必须注明版本

每次正式实验至少记录：

```text
代码 commit
数据集版本
模型版本
随机种子
参数配置
硬件环境
```

例如：

```text
commit: a82c91f
dataset: v1.2
seed: 42
model: yolov11n
```

---

## 3. 测试集禁止参与训练

所有最终指标必须来自：

```text
test set
```

训练集 Accuracy、训练集 Loss 不得作为最终实验结论。

---

## 4. Baseline 与最终方法必须使用同一测试集

否则不同方法之间的指标不可直接比较。

---

## 5. 正式实验建议重复运行

如果训练成本允许，核心实验建议使用：

```text
seed = 42
seed = 3407
seed = 2026
```

最终论文报告：

```text
平均值 ± 标准差
```

例如：

```text
92.4 ± 0.6
```

如果时间或算力不足，至少保证核心实验重复 3 次。

# 十五、当前阶段最优先确认的内容

6号当前阶段不需要优先训练模型，而应先统一实验标准。

当前最优先完成以下三件事：

1. 将本实验规范同步给 1～5 号负责人。
2. 建立统一的 `experiments/` 目录和 CSV 模板。
3. 与 1号、3号、4号共同确定动作类别、标准工序和异常类型。

建议第一版统一定义：

```text
标准工序：
挖掘 → 提升 → 回转 → 卸料 → 返回

动作类别：
挖掘
提升
回转
卸料
返回
等待

异常类型：
漏步骤
顺序错误
重复步骤
非法动作
动作未完成
```

上述定义需要结合实际施工工艺和真实数据进一步确认，确认后不应频繁修改，否则会影响数据标注、动作识别、工序判断及最终实验的一致性。
